# CLAUDE.md — muneebgrad

## Overview

`muneebgrad` is a Python library scaffold built with **nbdev** (v2). It is in a very early state (v0.0.1, Alpha status) with a single placeholder module (`core.py`) exporting a stub `foo()` function. The library is not published to PyPI or conda (install from GitHub), and is documented via Quarto on GitHub Pages.

All real source code lives in **Jupyter notebooks under `nbs/`**; Python files under `muneebgrad/` are **autogenerated** and must not be edited directly.

## Tech Stack

- **nbdev** — notebook-driven development (notebooks are the source of truth)
- **Quarto** — documentation site generation
- **setuptools** — packaging via `setup.py` + `pyproject.toml`
- **Python >= 3.9**, Apache 2.0 license
- GitHub Actions CI via `fastai/workflows`

## Key Directories and Files

```
nbs/                    # Source notebooks — edit these, not muneebgrad/
  00_core.ipynb         # Core module notebook (exports to muneebgrad/core.py)
  index.ipynb           # Becomes README.md and docs index page
  nbdev.yml             # Quarto site metadata
  _quarto.yml           # Quarto rendering config (theme, layout)

muneebgrad/             # Auto-generated Python package — DO NOT EDIT
  core.py               # Generated from nbs/00_core.ipynb
  __init__.py           # Auto-managed version string
  _modidx.py            # Auto-generated module index for nbdev

_proc/                  # Processed notebooks (intermediate nbdev output) — gitignored
settings.ini            # Single source of truth for all project metadata
setup.py                # Reads settings.ini; do not edit directly
pyproject.toml          # Build system declaration only (setuptools)
```

## Build / Run / Test / Lint Commands

All commands assume the venv is active: `source .venv/bin/activate`

| Task | Command |
|------|---------|
| Install in dev mode | `pip install -e .` |
| Export notebooks → Python | `nbdev_export` |
| Run tests | `nbdev_test` |
| Clean notebook metadata | `nbdev_clean` |
| Full prepare (export + test + clean) | `nbdev_prepare` |
| Build docs locally | `nbdev_docs` (requires Quarto) |
| Preview docs | `nbdev_preview` |
| Build sdist/wheel | `python -m build` |
| Publish to GitHub Pages | `nbdev_docs` then push |

## nbdev Conventions

- **`#| export`** — cell directive: include this cell in the generated `.py` module
- **`#| hide`** — cell directive: exclude from docs but keep in notebook execution
- **`#| default_exp <name>`** — sets the module file that this notebook exports to
- **`tst_flags = notest`** — cells tagged `notest` in `settings.ini` are skipped by `nbdev_test`
- **`black_formatting = False`** — Black is not applied on export
- Notebook numbering convention: `00_core.ipynb` → `muneebgrad/core.py`; add new modules as `01_foo.ipynb`, etc.

## Workflow for Adding Code

1. Edit or create a notebook in `nbs/`
2. Add `#| export` to cells that should become library code
3. Run `nbdev_prepare` to export, test, and clean in one step
4. Commit both the notebook and the generated `.py` file

## CI

- **test.yaml** — runs on every push/PR via `fastai/workflows/nbdev-ci@master` (executes `nbdev_test` on all notebooks)
- **deploy.yaml** — on push to `main`/`master`, deploys Quarto docs to GitHub Pages via `fastai/workflows/quarto-ghp@master`

## Gotchas

- Never edit files in `muneebgrad/` directly — they are overwritten by `nbdev_export`. Always edit the corresponding notebook in `nbs/`.
- `_proc/` is gitignored (nbdev intermediate output). It will be regenerated automatically.
- `README.md` is autogenerated from `nbs/index.ipynb` by `nbdev_prepare`. Editing `README.md` directly will be overwritten.
- The `.venv/` directory is present locally but gitignored; it contains nbdev, Quarto tooling, and Jupyter.
- `settings.ini` is the canonical metadata source — `setup.py`, pyproject, and docs all derive from it. Update version, description, and requirements there.
- No runtime dependencies are declared yet (`requirements` in `settings.ini` is commented out).
